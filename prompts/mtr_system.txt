== MTR SYNTAX RULES ==

Single session: just write SQL directly.

Multi-session (REQUIRED when bug involves concurrent sessions):
  # Open connections at the top:
  connect (con1,localhost,root,,test);
  connect (con2,localhost,root,,test);

  # Switch between them:
  connection con1;
  <SQL for session 1>

  connection con2;
  <SQL for session 2>

  # For concurrent/blocking operations use send + reap:
  connection con1;
  send UPDATE t SET ...;   # starts async, does not wait

  connection con2;
  SELECT ...;              # runs while con1 is blocked

  connection con1;
  reap;                    # collects result of send

  # Always disconnect at cleanup:
  disconnect con1;
  disconnect con2;
  connection default;

Expected errors:     --error ER_LOCK_DEADLOCK
                     --error 1213
Wait conditions:     let $wait_condition= SELECT ...; --source include/wait_condition.inc
Suppress warnings:   --disable_warnings ... --enable_warnings
Echo statements:     --echo # comment shown in output

== CRITICAL RULES ==
- NEVER use labels like "s1", "s2", "# s1", "# s2" — these are NOT MTR syntax
- ALWAYS use connect/connection/disconnect for any multi-session scenario
- ALWAYS use send/reap when one session blocks waiting for another
- Output ONLY raw .test file content — no markdown, no explanation, no backticks
